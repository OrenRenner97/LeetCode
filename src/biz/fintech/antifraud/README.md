# fintech/antifraud — детектор card testing

**Боль.** У мошенника украденная база карт. Чтобы понять, какие живые, он с одного устройства или IP делает подряд много мелких платежей (1 ₽, 10 ₽), каждый раз с **новой** картой. Большинство отклоняется. Живые карты он потом продаёт дороже или тратит. Магазин получает штрафы от платёжных систем и комиссии за каждую попытку, а владельцы карт — списания.

**Алгоритм.** [LeetCode 3. Longest Substring Without Repeating Characters](../../../../problems/0003_longest_substring_without_repeating_characters/README.md): «строка» — отпечатки карт в попытках одного источника по времени, «без повторов» — разные карты подряд. Вызов: `algos.longest_unique_window(cards, max_repeats=k)`.

## Правило (`CardTestingRule`)

| Параметр | По умолчанию | Смысл |
|----------|--------------|-------|
| `min_cards` | 5 | от скольких разных карт подряд поднимать тревогу |
| `max_repeats` | 1 | сколько раз карта может встретиться в окне. `2` ловит обход «каждую карту по два раза» |
| `high_decline_rate` | 0.5 | доля отказов, с которой риск `HIGH` |

Результат по источнику:
- **`HIGH` → `block`**: много разных карт подряд **и** много отказов. Почти наверняка перебор;
- **`MEDIUM` → `review`**: много карт, но платежи проходят. Это может быть семья, офис, кафе с общим Wi-Fi (NAT) или аккуратный мошенник. Блокировать опасно, отправляем на ручной разбор.

## Бизнес-детали

- **Номер карты (PAN) детектору не нужен и не должен к нему попадать** (PCI DSS). На вход идёт отпечаток (хэш PAN с солью) и последние 4 цифры для отчёта. API отклоняет поле, похожее на номер карты (422).
- **Порядок важен.** Окно — это подряд идущие попытки, поэтому детектор сам группирует поток по источнику и сортирует по времени: события в реальности приходят вперемешку.
- **Источники не смешиваются.** 3 карты с одного IP и 3 с другого — это не 6 карт подряд.
- **Обход через повторы.** Если мошенник пробует каждую карту дважды (`aabbcc…`), строгое правило видит окна по 2 карты. С `max_repeats=2` окно снова ловится. Это прямое применение обобщения из шага 1.5.
- **Ограничение пакетного режима:** по источнику сообщается одно, самое длинное окно. Две атаки с одного IP в разное время дадут одну тревогу, и этого достаточно для блокировки. При `max_repeats > 1` самое длинное окно не обязательно содержит больше всего разных карт («aabbcc» длиннее «abcd», но карт в нём 3, а не 4), поэтому в редких случаях пакетный режим пропустит то, что поймает потоковый.

## Два режима

| | `CardTestingDetector.scan()` (пакетный) | `StreamingCardTestingDetector.observe()` (онлайн) |
|-|-----------------------------------------|---------------------------------------------------|
| Когда | ночной/часовой отчёт по истории | каждая попытка оплаты в реальном времени |
| Как | группировка, сортировка, **один** вызов `longest_unique_window_batch` (numba `prange` по источникам) | окно каждого источника в памяти: попытка входит и выходит по разу → O(1) амортизированно |
| Тревога | самое длинное окно источника | в момент, когда окно стало подозрительным; повторно — только при эскалации до HIGH |
| Скорость | 10⁶ попыток за ~2 s, из них алгоритм 0.065 s, остальное — Python-объекты | **~430 000 попыток/с** на чистом Python |
| Память | вся история за период | только текущие окна; `forget_idle()` выбрасывает молчащие источники |

Подробные замеры и выводы (закон Амдала, ловушка с сортировкой строк) — в [README задачи 3, шаг 3](../../../../problems/0003_longest_substring_without_repeating_characters/README.md).

# biotech/cloning — рестрикционный анализ и проверка праймеров

**Боль.** Молекулярное клонирование — ежедневная работа лабораторий, биотех-компаний и сервисов синтеза ДНК: вставить ген в плазмиду, размножить, проверить. Перед каждым экспериментом нужно ответить на вопросы:
- **где режет фермент** (карта рестрикции плазмиды или гена);
- **чем открыть вектор**: фермент должен резать его ровно один раз и только в полилинкере (MCS), а вставку не резать вовсе, иначе она развалится;
- **как проверить клон**: какие фрагменты покажет гель после переваривания, если вставка встала, и если нет;
- **годится ли праймер**: участок, равный своему обратному комплементу, позволяет двум копиям праймера слипнуться (self-dimer), и ПЦР даёт мусор вместо продукта.

Ошибка выясняется только через дни работы и реактивы, поэтому эти проверки делают заранее и в программе.

**Связь с задачей.** [LeetCode 5. Longest Palindromic Substring](../../../../problems/0005_longest_palindromic_substring/README.md). Сайт почти любого рабочего фермента рестрикции II типа — **палиндром относительно комплемента**: `GAATTC` на одной цепи читается как `GAATTC` и на другой (5'→3'). Это палиндром «с отображением» A↔T, C↔G, и его ищет `algos.palindrome_radii(seq, mirror=COMPLEMENT)` — алгоритм Манакера из задачи.

## Как ищутся сайты (`find_sites`)

1. Один проход Манакера даёт для каждого центра между нуклеотидами длину максимального комплементарного палиндрома.
2. Сайт длины L с центром c есть, только если радиус в c ≥ L. Такие центры в случайной ДНК редки (радиус ≥ 4 — примерно 1/16, ≥ 6 — 1/64).
3. На них вырезаем подстроку нужной длины и ищем её в словаре `сайт → ферменты` (отдельный словарь на каждую длину).

Время — O(n + число палиндромных центров × число разных длин сайтов), **почти не зависит от размера каталога**. Изошизомеры (SmaI и XmaI на `CCCGGG`) и вложенные сайты (MspI `CCGG` внутри `CCCGGG`) находятся на одном центре.

## Правила

- **Только палиндромные ферменты без N** (`Enzyme` проверяет это при создании). Ферменты IIS (BsaI, `GGTCTC`) режут вне сайта и не палиндромны: для них нужен обычный поиск подстроки по обеим цепям. Вырожденные сайты (`GANTC`) требуют сравнения по маске IUPAC.
- **Кольцевая ДНК** (`circular=True`): плазмида замкнута, сайт может проходить через «начало» записи. Начало дописывается в конец, сайты, начинающиеся в дописанном куске, отбрасываются (они уже найдены в начале).
- **Разрез** — позиция на верхней цепи (`cut`: разрез между `cut - 1` и `cut`). Для кольца берётся по модулю длины.
- **Концы и совместимость**: `ends` (5'/3'/blunt) и `overhang`. BamHI `G^GATCC` и BglII `A^GATCT` дают одинаковый выступ `GATC`, и их фрагменты сшиваются друг с другом. Изошизомеры SmaI (тупые) и XmaI (5') — один сайт, разные концы.
- **Переваривание** (`digest`): линейная ДНК с k разрезами → k + 1 фрагмент; кольцо → k фрагментов, без разрезов — одна молекула исходной длины. Разрез на самом краю линейной ДНК фрагментом не считается.
- **Кандидаты для клонирования** (`cloning_candidates`): ровно один сайт в векторе, сайт целиком внутри полилинкера, ни одного сайта во вставке.
- **Праймер** (`check_primer`): `SELF_DIMER`, если самый длинный самокомплементарный участок длиннее `max_stem` (6) или участок на 3'-конце длиннее `max_3prime_stem` (3). 3'-конец опаснее: полимераза достраивает слипшиеся праймеры. Участок на 3'-конце — максимальный палиндром, который заканчивается на конце праймера (`maximal_palindromes`).
- **Вход**: A, C, G, T, N; регистр, пробелы и переводы строк игнорируются (FASTA можно вставлять как есть, без заголовка). `N` не совпадает ни с чем. Праймер с `N` → `HAS_N`.

## Что взяли бы в проде

- **Полный каталог REBASE** (сотни коммерческих ферментов), вырожденные и непалиндромные сайты, чувствительность к метилированию (Dam/Dcm блокируют, например, XbaI и ClaI).
- **Термодинамика праймеров** (ΔG димеров и шпилек, Tm) — primer3. Шпилька — это палиндром с петлёй в середине, его этот модуль не ищет. Здесь быстрый фильтр, который отсекает явный брак до дорогого расчёта.
- **Направленное клонирование**: пары ферментов с несовместимыми концами по краям вставки, чтобы она встала в нужной ориентации.
- **Хранилище последовательностей** (GenBank-файлы с аннотациями) вместо передачи ДНК в каждом запросе.

**Скорость (шаг 3).** `find_sites` на 10⁶ п.н. по всему каталогу: 1.59 s на Python → 0.15 s с нативным Манакером (`backend` не задан → `auto`). Ускорение ядра само по себе дало только ×5, потому что время ушло в Python-разбор. Остальное дали правки модуля: только палиндромные центры (`maximal_palindromes` фильтрует их векторно), `Site` как `NamedTuple`, проверка алфавита регуляркой. Праймеры короткие: для них `auto` остаётся на Python (50 µs против 82 µs у нативных).

# edtech/railfence — шифр «изгородь» для заданий по криптографии и CTF

## Боль

Платформам обучения криптографии, CTF и квестам нужны задания на классические шифры. Задание надо сгенерировать, объяснить картинкой, проверить ответ и, если участник застрял, подсказать. Онлайн-утилиты для «изгороди» обычно не поддерживают сдвиг начала зигзага, а при взломе выдают список кандидатов, не сообщая, можно ли ему верить.

**Защитой данных этот шифр не является**: все ключи перебираются за ~0.1 s. Модуль нужен для обучения и задач, а не для секретов.

## Связь с задачей

Шифрование — это ровно **LeetCode 6. Zigzag Conversion**: записать текст зигзагом по `rails` строкам и прочитать построчно (`algos.zigzag_encode`). Расшифровка — обратная перестановка (`algos.zigzag_decode`), которой в LeetCode нет. Картинка — `algos.zigzag_rows`.

## Что есть, чего нет в LeetCode

- **Сдвиг `offset`**: зигзаг начинается не с верхней строки, а с фазы `offset` (0 ≤ offset < 2·(rails − 1)). Реализован так: перед текстом дописываются пустышки, после шифрования они выбрасываются. При расшифровке их места даёт зашифрованная маска.
- **Картинка** (`grid`) — как в условии задачи: строки с точками на пустых местах.
- **Подготовка текста**: `letters_only` (буквы, верхний регистр, Ё → Е) и `group` (блоки по 5).
- **Взлом без ключа** (`crack`): перебор всех `(rails, offset)` до `max_rails` (по умолчанию 40, это 1 560 ключей), одинаковые расшифровки схлопываются.

## Как взлом выбирает ответ

Перестановка не меняет состав букв, поэтому частоты отдельных букв у всех кандидатов одинаковы. Различает их только **порядок**. Модель языка — пары букв по небольшому авторскому корпусу (`corpus_en.txt`, `corpus_ru.txt`, ~4 КБ). Вклад пары `ab` равен `log P(ab) − log P(a) − log P(b)`, со сглаживанием 0.5: частые пары (TH, СТ) дают плюс, невозможные стыки (DN, ЪЫ) — сильный минус. `score` — средний вклад пары. У настоящего текста он > 0 (~0.2–0.4), у перемешанных букв < 0 (~−0.5…−0.7).

Первая версия брала только 50 самых частых пар без штрафа за редкие. Мусор вроде «old statione at the dnight» обгонял правильный текст: на 100 символах верно было 52 из 60 вместо 55 из 60, а на 50 символах — 31 из 60 вместо 41 из 60.

**Повороты — настоящая неоднозначность шифра.** Другой `offset` при том же `rails` часто расшифровывает текст в его **циклический поворот**: «n in the presence…» против «in the presence… n». Перебор на уникальных символах нашёл 2 434 таких пары ключей. Биграммы у текста и его поворота отличаются одной парой на стыке, поэтому статистика их не различит. Взлом выделяет повороты лучшего кандидата в `rotations` и считает уверенность против лучшего **не-поворота**. Выбрать среди поворотов может только человек, обычно по обрезанному слову в начале.

## Калибровка `confident`

80 случайных отрывков на каждую длину, ключи `rails` 2–12 со случайным сдвигом, половина отрывков без пробелов. Тексты не из корпуса модели.

| язык | символов | лучший = текст | текст среди лучшего и его поворотов | `confident` | уверен, но неверно |
|------|----------|----------------|--------------------------------------|-------------|--------------------|
| en | 20 | 27 | 30 | 0 | 0 |
| en | 50 | 57 | 62 | 31 | 0 |
| en | 100 | 71 | 76 | 47 | 0 |
| en | 200 | 70 | 72 | 42 | 0 |
| ru | 20 | 37 | 40 | 0 | 0 |
| ru | 50 | 56 | 60 | 31 | 0 |
| ru | 100 | 67 | 71 | 37 | 0 |
| ru | 200 | 72 | 76 | 51 | 0 |

- Порог разрыва между лучшим и лучшим не-поворотом — 0.1. При 0.3 уверенность была только в ~25% случаев (тоже без ошибок).
- **Минимум 40 букв**: на 30 символах при пороге 0.1 было 1 и 3 уверенных ошибки из 80.
- Если `confident = False`, ответ надо проверить глазами среди `candidates` и `rotations`.

## Запуск

```bash
uv run python -m biz.edtech.railfence.demo
```

API: `POST /v1/edtech/railfence/encrypt`, `/decrypt`, `/crack`. Взлом: ~0.1 s на 60 букв, ~1.8 s на 5 000 символов (поэтому в API лимит 2 000).

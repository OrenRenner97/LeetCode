# 8. String to Integer (atoi)

[LeetCode](https://leetcode.com/problems/string-to-integer-atoi/) · Medium · String

## Условие (кратко)
Перевести строку в 32-битное знаковое целое, как `atoi` в C: пропустить ведущие пробелы (только `' '`), прочитать необязательный знак `+`/`-`, затем цифры до первой не-цифры. Нет цифр — 0. Результат вне [−2³¹, 2³¹ − 1] прижать к ближайшей границе.

## Решение (solution.py): один цикл с флагами состояния

**Идея:** один проход по символам. Что сейчас разрешено, решают два флага: `sign` (0 — знака ещё не было, ±1 — был) и `has_number`. Пробел до знака и цифр пропускается, после них обрывает разбор. Второй знак или знак после цифр тоже обрывают. Цифры копятся в `result`, в конце результат умножается на знак и прижимается к границам.

**Время:** O(n) · **Память:** O(1) на символ, но `result` растёт до O(n) цифр

Проходит все assert'ы из `tmp.py`, включая `"  +  413"`, `"0-1"`, `"+-12"` и 101-значное число.

Что можно улучшить (почему код кажется некрасивым):
- **Три последовательные фазы склеены в один цикл.** Сам алгоритм — это три фазы подряд: пробелы → знак → цифры. Цикл `for char in s` обрабатывает все символы одинаково, поэтому фазу приходится восстанавливать по флагам (`sign == 0`, `has_number`). Отсюда проверки вида «пробел, но если уже был знак или цифра, то стоп». Если пройти фазы по очереди, двигая индекс `i`, флаги не нужны: в каждой фазе свой маленький `while`.
- **`sign` хранит две вещи сразу:** знак и факт «знак уже прочитан» (значение 0). Из-за этого на первой цифре нужно ещё выставить `sign = 1`. Это скрытая связь между ветками.
- **Три ветки делают одно и то же.** У веток «буква» и `'.'` внутри `if has_number: break` + `break`, то есть просто `break`, как в `else`. Все три сворачиваются в `else: break`. Попутно: `ord(char) in range(ord('a'), ord('z') + 1)` — это `'a' <= char <= 'z'`.
- **`str.isdigit()` шире, чем `0-9`.** Он принимает `'²'`, `'٣'` и другие Unicode-цифры, а `ord(char) - ord('0')` для них даёт мусор: `myAtoi('1²') == 140`, `myAtoi('٣') == 1587`. По ограничениям LeetCode таких символов нет, но для библиотеки это баг. Надёжнее `'0' <= char <= '9'`.
- **Число копится без ограничения.** На `"1" + "0"*100` строится 101-значный int и только потом прижимается. В Python это работает, а в языке с 32-битным int здесь было бы переполнение (та же ловушка, что в задаче 7). Можно остановиться, как только `result` перевалил за границу: дальше ответ уже известен.
- **Магические числа.** `2147483647` и `-2147483648` лучше вынести в `INT_MAX`/`INT_MIN`, а прижатие записать как `max(INT_MIN, min(INT_MAX, x))`.

## Шаг 1. Альтернативы (alternatives.py)

| Подход | 32 бита? | typical, 10⁵ вызовов | Идея |
|--------|----------|------|------|
| Solution | нет | 286 ms | один цикл, фаза по флагам `sign` / `has_number` |
| Phases | нет | 353 ms | три фазы подряд по индексу `i`: пробелы → знак → цифры, флагов нет |
| **PhasesGuard** | **да** | 250 ms | то же, копим в отрицательных и **останавливаемся у границы**, как в C |
| **Regex** | нет | **121 ms** | ` *([+-]?[0-9]+)` + `int` + прижатие |
| StripPrefix | да* | 189 ms | фазы через `lstrip(' ')`, `lstrip(цифры)` — C-методы вместо цикла |
| Automaton | нет | 307 ms | таблица переходов «состояние × класс символа» (официальный разбор) |

\* `int()` только от ≤ 10 цифр: если цифр больше, ответ — граница, большой int не строится.

Все O(n), n ≤ 200. Различаются читаемостью, тем, растёт ли число за пределы int32, и ценой вызова.

- **Phases** — ответ на «почему некрасиво». Тот же алгоритм, но порядок фаз задаёт порядок кода, а не флаги: три коротких `while`, каждый про одно. Ветки «буква», `'.'` и «другое» исчезают сами: цикл цифр просто кончается. Цифры проверяются через `'0' <= c <= '9'`, а не `isdigit()`.
- **PhasesGuard** — строгий вариант для языка с int32 и каноничный для собеседования. Это `NegativeAccumulate` из задачи 7: −2³¹ существует, +2³¹ нет, поэтому копим со знаком минус и проверяем *до* шага `rev·10 − d`. Бонус, которого в задаче 7 не было: переполнение = **ответ известен** (граница), дальше строку можно не читать. Поэтому на long он в 7 раз быстрее Phases.
- **Regex** — самый короткий и самый быстрый: вся грамматика — одна строка, разбор — C-цикл движка `re`. Ловушка: `\d` в Python матчит Unicode-цифры (`'٣'`), поэтому `[0-9]`. Минус — строит большой int: на 200 цифрах это ещё дёшево, на мегабайтной строке `int()` упрётся в лимит 4 300 цифр (`ValueError`).
- **StripPrefix** — те же фазы встроенными методами строк. Трюк: `len(t) - len(t.lstrip("0123456789"))` — длина префикса из цифр без Python-цикла. Ведущие нули срезаются `lstrip("0")`, и если осталось > 10 цифр, ответ — граница без `int()`.
- **Automaton** — правила в таблице, а не в `if`-ах. Ваше решение — это тот же автомат, только состояние закодировано парой флагов, а переходы размазаны по веткам. Таблица выигрывает, когда грамматика растёт (`_` между цифрами, `0x`, экспонента), но в Python она самая медленная: на каждый символ — вызов функции классификации.
- Все альтернативы отклоняют Unicode-цифры (`test_unicode_digits_rejected`). Solution на них даёт мусор (`'1²'` → 140), поэтому этот тест — только для альтернатив.

### Бенчмарк (`uv run benchmarks/string_to_integer_atoi.py`)

Пачка из 10⁵ вызовов `[f(s) for s in xs]`, Python 3.12, медиана из 5. Ноутбук: между двумя прогонами всё плавало до ×2, порядок мест стабилен.

| Вход | Regex | StripPrefix | PhasesGuard | Solution | Automaton | Phases |
|------|---|---|---|---|---|---|
| typical (`"  -1234abc"`, 1–10 цифр) | **121 ms** | 189 ms | 250 ms | 286 ms | 307 ms | 353 ms |
| garbage (сразу буква → 0) | **42 ms** | 100 ms | 49 ms | 57 ms | 91 ms | 76 ms |
| long (~180 символов, переполнение) | **225 ms** | 677 ms | 861 ms | 5.41 s | 7.43 s | 6.17 s |

Выводы:
- **Regex выигрывает везде, даже на garbage**, где разбор занимает пару символов. Скомпилированный `re` — это C-цикл по символам; Python-цикл стоит ~30–50 ns на символ только на байткоде.
- **Ранняя остановка решает на длинном входе:** PhasesGuard ×7 быстрее Phases. Те читают все ~150 цифр и растят int до 150 знаков (каждый шаг `result·10 + d` — O(длина)), то есть O(n²) по цифрам. PhasesGuard после ~10 значащих цифр выходит.
- **Phases медленнее Solution, хотя делает то же самое.** Причины: `s[i]` с проверкой `i < n` дороже, чем `for c in s`, а `_clamp` (вызов функции + `max` + `min`) стоит ~0.35 µs — на коротких строках это четверть времени. PhasesGuard прижимает без функции и потому быстрее обоих. Красота в Python не бесплатна, но и не дорога: разница в пределах ×1.3.
- **StripPrefix: `lstrip` с набором из 10 символов не бесплатен.** На каждый символ строки он ищет его в наборе, поэтому на long Regex в 3 раза быстрее. А на garbage его фиксированные расходы (пять методов и срезов) делают его хуже простых циклов.
- **В C порядок был бы обратным:** регулярка — тяжёлая библиотека, а цикл PhasesGuard — пара тактов на символ. Каноничный `atoi`/`strtol` в libc и есть PhasesGuard.

## Шаг 1.5. Библиотека → `algos.parse_int_prefix`
`src/algos/parsing/atoi.py` (новая техника `parsing`). LeetCode 8 = `r.value if (r := parse_int_prefix(s)) else 0`. Отличия от LeetCode-версии:
- **`None`, если цифр нет**, а не 0: у LeetCode `"abc"` и `"0"` неразличимы.
- **`IntPrefix(value, end, clamped)`**: `end` — как `endptr` у `strtol` (где кончился разбор, `s[end:]` — отброшенный хвост), `clamped` — было ли прижатие.
- **Любые `base` (2…36, регистр букв любой), `bits` (или `None` — без ограничения), `signed`**; `whitespace` — какие символы пропускать (у LeetCode `' '`, у C — ещё `\t\n\v\f\r`).
- Только ASCII-цифры (`[0-9]`, не `\d`).
- Реализация — регулярка (самая быстрая на шаге 1). Если значащих цифр больше, чем у границы, ответ — граница без `int()`, как в StripPrefix. Поэтому 300-значная строка не строит большой int и не упирается в лимит 4 300 цифр (при `bits=None` упирается — это в docstring).

Тесты `tests/algos/test_parse_int_prefix.py`: все кейсы и эталон задачи, `None` против 0, `end`/`clamped`, все границы для bits 1…64, основания 2–36, валидация.

## Шаг 2. Бизнес-кейс → `biz.infra.envconfig`
**Боль.** Числовые настройки в env: `TIMEOUT_SEC=30s`, `WORKERS=auto`, `BATCH=1_000`. C-сервис (`atoi`) молча читает 30, 0 и 1, Python-сервис (`int()`) падает или читает 1000. В смешанном стеке одна переменная — два значения.
**Связь с задачей.** Разбор C-сервиса — это ровно atoi. `None` отличает `auto` от `0`, `end` показывает отброшенный хвост, `clamped` — переполнение типа (`4294967296` в int32).
Подробности: `src/biz/infra/envconfig/README.md`. API: `POST /v1/infra/envconfig/audit`.
